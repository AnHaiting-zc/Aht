# 05｜流程图型｜Process Infographics

## 1. 类型定义
流程图型信息图以步骤、阶段、状态变化或操作顺序为核心信息关系，回答“先做什么、接着做什么、经过哪些环节、最终得到什么”。它可以表现线性流程、分支流程、循环流程、泳道流程或具有连续视觉路径的步骤叙事。

流程图型强调的是过程关系，而不限定必须使用传统矩形框和箭头。编号、连续路径、阶段插画、连接线、方向符号都可以承担流程导航。

## 2. 核心数据逻辑
典型数据结构包括：
- Step：步骤编号、名称、说明；
- Sequence：步骤先后关系；
- Input：步骤输入的材料、信息或状态；
- Action：操作或处理；
- Output：步骤产生的结果或新状态；
- Condition：分支条件（若存在）；
- Duration：持续时间（若有来源）。

基本关系可表示为：输入 → 操作 → 输出 → 下一步骤。若流程存在并行、回流或条件分支，应在图面中明确表达，不能只靠装饰曲线暗示。

## 3. 主要视觉形式
- 线性流程：节点按单一顺序排列；
- 连续路径流程：以曲线、带状路径或蛇形路线连接步骤；
- 分支流程：根据条件分为多个路径；
- 循环流程：通过回环箭头表达重复；
- 泳道流程：按角色、部门或系统分区；
- 图解式流程：步骤节点配合具体操作插画。

## 4. 判定标准
- 存在两个或以上可辨识的步骤／阶段；
- 步骤之间具有明确先后、依赖、分支或循环关系；
- 编号、箭头、路径或版面位置支持读者理解顺序；
- 全图主要任务是解释过程，而不是单纯展示对象目录或统计结果。

若仅有多个并列对象而无操作顺序，不应归为流程图型。若仅有单张操作场景插画而没有阶段关系，则更接近示意图或说明图。

## 5. 视觉编码分析维度
- 顺序编码：数字、字母、方向箭头；
- 路径编码：线条、带状路径、节点连接；
- 阶段编码：颜色、分区、容器或背景；
- 动作编码：人物、器具、对象状态变化；
- 输入输出编码：原料、半成品、成品；
- 时间编码：时长标签、等待提示、时间轴（仅在数据明确时）。

## 6. 与How-to示意图的区别
- Process强调步骤之间的顺序和依赖关系。
- How-to强调具体操作如何完成，通常以动作示意和说明文字为核心。
- 食谱、装配、实验操作等作品可能同时具备两种特征；应依据整张图的主叙事任务确定唯一主分类，并保留交叉标签。

## 7. 质量控制
- 步骤编号必须与实际工艺依赖一致；
- 若前置准备在后续步骤才出现，应明确标注“提前准备”或调整顺序；
- 区分流程路径和装饰性曲线，避免读者误读；
- 时长、数量、温度等信息必须有明确来源；
- 保证步骤文字与动作插画一致；
- 复杂流程可按准备、加工、组装、完成等阶段分组；
- 为输入、处理、输出建立清晰视觉对应。

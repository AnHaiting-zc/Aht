# 02 信息图形类型案例

本文件夹用于**用户提供的案例图片、逐图案例分析、类型说明与持续迭代的设计原则**。

## 类型说明
1. [混合型信息图形 Mixed Charts](01-混合型信息图形%20Mixed%20Charts.md)
2. [文字型／列表型信息图形 Informational / List Infographics](02-文字型列表型信息图形%20Informational%20List%20Infographics.md)
3. [时间轴型信息图形 Timeline Infographics](03-时间轴型信息图形%20Timeline%20Infographics.md)

## 与 01 文件夹的职责分离
- `01-信息图形数据逻辑`：保存抽象定义、数据结构、统计方法和视觉原理，**不保存案例图片**。
- `02-信息图形类型案例`：保存图像案例及观察记录、实例证据、反例和提炼后的原则。
- 一张图片可对应多种信息逻辑，但须注明**主类型／辅助类型**；使用相对 Markdown 链接双向关联。

## 推荐的新增案例组织
```text
02-信息图形类型案例/
├── README.md
├── 01-混合型信息图形 Mixed Charts.md
├── 02-文字型列表型信息图形 Informational List Infographics.md
├── 03-时间轴型信息图形 Timeline Infographics.md
└── 案例/
    └── MIX-001/
        ├── 原图.png
        └── 案例分析.md
```
`案例/` 目录在收到第一张案例时实际创建（Git 不跟踪空目录）。

## 图片分析与维护协议
1. 收到用户案例图后，根据可见内容先做客观描述，再明确不确定的数据与推测。
2. 建立案例编号：混合 `MIX-001`，文字列表 `LST-001`，时间轴 `TML-001`。
3. 图片保存在对应 `案例/<编号>/` 下；案例分析引用本地原图路径，保留来源和版权信息（未知则标未知）。
4. 用 A 数据逻辑、B 统计图形与计算、C 视觉编码、D 信息架构、E 视觉叙事统一分析。
5. 在类型说明里增补由案例支持的可复用原则，写明案例编号；同步补充与 01 理论文件的**文本超链接**。
6. 遇到反例或新类型，修订原则并记录更新日志；不因新增案例而删去有价值的例外情况。
7. **更新触发方式：** 用户提供新案例并请求处理后更新 GitHub；当前不会后台自动监测图片或实时更新。
8. 任何案例观察不得凭空推断统计来源、公式、作者或授权。
